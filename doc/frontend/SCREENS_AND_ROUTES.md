# Frontend 画面・ルート仕様

## 認証前（共通レイアウトなし）

| パス | コンポーネント | 概要 |
|------|----------------|------|
| `/login` | LoginPage | ログイン（メール＋パスワード、および「Microsoft でログイン」）。クエリ `ssoCode` でワンタイム交換、`ssoError` でエラー表示。本番では「テストユーザーでログイン」は非表示 |
| `/force-password-change` | ForcePasswordChangePage | `user.status === 'pending'` の初回ログイン時に強制表示するパスワード変更画面。変更完了まで他画面へ遷移不可 |
| `/register` | RegisterPage | 新規登録 |
| 上記以外 | Navigate to `/login` | 未認証時はログインへ |

## 認証後（Layout 内）

### ランディング

| パス | 動作 |
|------|------|
| `/` | `user.landingPage` に応じて `/home` \| `/projects`（または従来値 `gantt` の場合は `/projects?view=gantt`）\| `/companies` にリダイレクト |

24px＋区切り線 1px）とし、時間記録行は従来どおり内容に応じた高さとする。プロジェクト／チケット／時間記録の階層は字下げ（段落）で区別する（チケットはプロジェクト配下に親子ツリーでインデントし、子チケットは `└` 付きで字下げ。時間記録は各チケット配下にインデント）。子を持つチケットは折りたたみ可能（折りたたみ時は配下の子チケットと時間記録を非表示）。一覧・ガント・カンバン・時間のいずれの表示でも、プロジェクト名は企業が設定されている場合「企業名 / プロジェクト名」の形式で表示する（企業未設定時はプロジェクト名のみ）。一覧表示では企業を独立した列としては表示しない（プロジェクト名に含めるため）。**プロジェクト登録／編集モーダル**の親プロジェクト候補は2段表示（上段: 企業名+祖先をグレー小さめ、下段: プロジェクト名。企業・祖先が無い場合は1段）。**時間**タブのチケット絞り込みに期限は含めない（UI非表示・初期値・フィルタ適用なし）。**ガント**／**カンバン**／**時間**ではチケットの開始日・終了日を対象とする期間（`scheduleDateStart`〜`scheduleDateEnd`）の範囲指定があり、指定期間がチケットの開始日〜終了日の期間と一部でも重なる場合に出力対象とする（片側のみ指定時は他端を無限として判定。チケット側は開始・終了の片方のみならその日を点として扱い、両方未設定は期間フィルタ指定時は既定では非対象。「開始・終了未設定を含む」（`includeUnscheduled`、省略時 false）をオンにすると、期間重なりと OR で開始・終了とも未設定のチケットも含める（当日作業の確認や電話対応などの汎用チケットへの工数記録向け）。親チケットは API 集約後の開始・終了を用いる（子から日付が付いていれば設定済み扱い）。開始・終了とも未設定のチケットには「日付未設定」ラベルを表示する（ガント: 左ペイン開始〜終了列、カンバン: カード、時間: ツリー行）。**ガント**／**カンバン**では従来どおりチケット期限フィルタも併用可能）。チケット条件の担当者は、先頭に「未割当」（担当ユーザー・担当グループのいずれも未設定のチケットを対象）、続けてグループ名を見出し行（選択可）とし、その直下に所属ユーザーを並べた階層一覧から複数選択する（グループ選択時はそのグループが担当グループとして割り当てられたチケットのみを対象とする（所属メンバーのユーザー担当は含めない）。いずれのグループにも属さないユーザーは「未所属」見出しの下に表示。「未割当」とユーザー／グループは OR 条件。ガント／カンバン／時間ではトラッカー・ステータス・担当者を `GET issues` / `GET gantt/*` の Query でサーバー絞り込みし、`assignedToIds` と `assignedToGroupIds` は OR。「未割当」含むときは担当者 Query を付けずクライアントで OR へ展開する）。フィルタパネルの日付範囲条件（プロジェクト期限日・チケット期限・チケット開始・終了・時間記録の記録期間）は「相対指定」と「直接指定」を切替可能。相対指定ではグループ（今日周辺／直近・将来／週単位／月単位／年度単位）付きの選択肢から選び、選択に応じて開始・終了日付へ値をセットする（年度は6月〜翌3月）。直接指定では日付を手入力する。保存済み検索では相対指定時は日付値を保存せずプリセットのみ保存し、適用時に再計算する。直接指定時は日付値も保存する。切替時のチケット検索初期値は担当者・開始・終了期間とも未指定（期間は直接指定・日付クリア）。時間記録は記録期間＝直接指定・日付クリア、記録者＝未指定。プロジェクトステータスおよび日付範囲条件の初期値は未指定（日付は直接指定かつクリア）。件数サマリーと「条件をすべてクリア」で一括リセット（時間タブ中は上記時間向け初期値に戻す）。表示モード・検索条件は ## 表示条件（メニュー・権限）

- サイドメニューは **権限設定の `canUse`** と `user.show*Menu` の両方を満たす場合に表示。
  - プロジェクト: `projects` の canUse + `showProjectsMenu`
  - 企業・連絡先・協会・法人格: 各対応コードの canUse + `showCompanyMenu`
  - 管理: `admin` の canUse + `showAdminMenu`
- ルートアクセス: 対応 feature の `canUse` が false の場合は `/` へリダイレクト。
- 新規/編集/削除ボタン: 対応 feature の `canInput` で制御。
- フォーム項目: 対応 field コードの `canInput` で disabled / 非表示。

## 管理 > 権限設定タブ

- **一覧**: 権限設定名、説明、割当グループ数、編集・削除
- **作成/編集モーダル**:
  - 基本情報（名前、説明）
  - **グループ割当**: 全グループをチェックボックスで複数選択（1 権限設定 → 複数グループ）
  - **権限マトリクス**: `scope=group` のカタログのみ（トップレベル `projects` 等）。プロジェクト詳細権限はロール側
- **グループタブ**: 一覧は親子階層の**ツリー表示**（親を持たないグループがルート。子はインデントし、子を持つ行は展開／折りたたみ可能。親を複数持つグループは各親の下に現れる。既定は全展開）。**ドラッグ＆ドロップ**で移動可能（`admin.groups` input）。行の間へドロップ＝同一親（またはルート）内の順番入れ替え。行の上へドロップ＝所属変更（通常ドロップは既存親をすべて外してドロップ先のみ親、**Ctrl/Cmd+ドロップ**はドロップ先を親として追加）。ルート領域へ通常ドロップで親なし。循環になる操作は API が 400。グループ詳細に権限設定名・親グループ・子グループを表示。一覧に親グループ名列。編集モーダルで権限設定ドロップダウン、**親グループ／子グループの複数選択**（自分自身は候補外）。入力: `admin.groups.fields.parentGroups` / `admin.groups.fields.childGroups` canInput（権限なし時は disabled。親変更を伴う DnD も同 field）。権限設定未割当時は「継承」表示。

## 管理 > ステータスタブ

- 表示: `admin.statuses` canUse。新規・編集・削除・並び替え: `admin.statuses` canInput。
- 登録・編集モーダルで **終了**（`isClosed`）チェックボックスを設定できる。入力: `admin.statuses.fields.isClosed` canInput（権限なし時は disabled。変更値は API に送らない）。
- 一覧およびロール編集の利用可能ステータス一覧では、終了フラグ付きステータスに「(終了)」を表示する。

## 管理 > ロールタブ

- ロール編集モーダルに **プロジェクト権限** マトリクス（`scope=role`：プロジェクト情報 / メンバー / issues / fields / wiki 等）。`projects.overview`（表示名: プロジェクト情報）と `projects.members`（メンバー）は独立した行で、使用・入力を分けて設定できる。`projects.saved-searches` は一覧機能のためロール対象外（グループ権限設定側）
- **初期ロール**（`isDefaultRole`）: プロジェクト概要のメンバー追加時にロール選択の初期値として使う。複数ロールに設定可能
- **利用可能なステータス**（RoleStatus）と **ステータス遷移**マトリクス（WorkflowTransition）を同一モーダルで設定。チケット作成・編集・カンバン移動で強制される（複数ロールは OR）。終了フラグ付きステータスは「(終了)」表示
- 既存ロールは seed / 起動時同期で全権限が付与される。RoleStatus / WorkflowTransition が未設定のロールは「全ステータス・任意遷移可」として扱う（後方互換）

## 管理 > 休日設定タブ

- 表示: `admin.holiday-settings` canUse。保存・追加・削除・祝日取込: `admin.holiday-settings` canInput。
- **曜日の休日**: 月〜日のトグル。休日にする曜日を `holidayWeekdays` に反映（内部は 0=日〜6=土）。
- **個別の休日**: 日付＋名称の一覧。手動追加・削除。**データ取得**ボタンで [国民の祝日 API](https://holidays-jp.github.io/api/v1/date.json) を取得し、即時取込せずモーダルで年単位グループ一覧を表示。年ごとの取込可否トグル後、確定で既存リストへ日付マージ（同日は名称上書き）。
- **個別の出勤**: 日付＋名称の一覧。曜日休日・個別休日より優先する出勤例外。
- ガント（プロジェクト一覧ガント含む）は `GET /settings/calendar` で読み、日表示の列強調と予定工数の営業日スキップに利用する。

## データの取得方針

- 各ページで必要な API を呼び出し（例: ProjectListPage → GET /api/projects、IssueListPage → GET /api/issues?projectId=...）。
- モーダル・タブは必要に応じて遅延取得または同一画面内でキャッシュを利用。

## 管理 > ユーザー画面のステータス運用

- 一覧上部で氏名・メール・所属グループ名による検索、およびステータス（有効・仮登録・無効）のチェックボックス絞り込みが可能。初期状態では「有効」「仮登録」にチェックが入り、「無効」はオフ（無効ユーザーのみを見る場合は「無効」をオンにする）。
- ユーザー登録・編集モーダルに `status` の入力 UI は表示しない。
- ユーザー新規登録モーダルに `password` の入力 UI は表示しない（仮パスワードはサーバー側で生成）。
- ユーザー新規作成時は常に `pending`（仮）として作成する。
- 新規作成時に生成された仮パスワードは登録メールアドレスに通知する（案内メールにログイン URL・メールアドレス・仮パスワードを記載）。
- 仮登録ユーザーに対し、確認ダイアログ後に登録メールを再送できる（仮パスワードも更新される）。表示条件は `status === 'pending'` かつ `canInput('admin.users')`。
- 一覧のアクション表示条件:
  - 登録メール再送アイコン: `status === 'pending'` かつ `canInput('admin.users')` のときのみ表示（確認後 `POST /admin/users/:id/resend-registration-email`）
  - 削除アイコン: `status === 'pending'` のときのみ表示
  - 無効化アイコン: `status === 'active'` のときのみ表示（確認後 `inactive` へ更新）
  - 有効化アイコン: `status === 'inactive'` のときのみ表示（確認後 `active` へ更新）
